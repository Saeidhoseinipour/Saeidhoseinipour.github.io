1. Introduction

Co-clustering partitions the rows and columns of a data matrix simultaneously. Classical objectives — the latent block model, non-negative matrix tri-factorization — need the number of blocks up front and struggle when the matrix is noisy and sparse. This article explores whether a large language model, used as an agent rather than a fixed classifier, can propose, critique and refine block structures.

The agent is not solving the optimization problem. It is supplying structural priors that a numerical solver can then exploit.

The pipeline has three stages: the LLM proposes an initial block count and a coarse assignment, a probabilistic model refines it, and the LLM evaluates the result and either accepts it or restarts with a new hypothesis.

2. Setup and notation

Let X ∈ ℝn×d be the data matrix with n rows and d columns. A co-clustering assigns each row i a row-block gi and each column j a column-block hj. The complete-data log-likelihood factorizes over blocks:

ℓ(X; g, h) = ∑i ∑j log f(xij | θgi hj)

With an exponential-family block model, each block carries its own natural parameter θkl. Sparsity is induced by a spike-and-slab prior on those parameters, which is where the agent's structural prior enters.

Narration

“Two things to remember. One: a co-clustering is just two labellings — one for rows, one for columns. Two: the likelihood factorizes over blocks, so if you get the blocks right, the rest is easy. The whole difficulty is choosing the blocks.”

3. The three-stage pipeline

  1. Propose. The LLM reads a short statistical description of the matrix and returns a candidate number of row blocks and column blocks, plus a rationale.
  2. Refine. A block model is fitted from that starting point until the objective converges.
  3. Judge. The LLM sees the score and the block summary and either accepts the result or asks for a revised proposal.
Narration

“Notice what the model is not doing. It never touches the numbers. It only says ‘try four row blocks and three column blocks’, and the solver does the real work. That keeps the method honest — every claim is still backed by a likelihood.”

4. Implementation

The agent wrapper is deliberately thin — it only ever emits JSON that describes a candidate block structure. 

import json
from dataclasses import dataclass

@dataclass
class Proposal:
    n_row_blocks: int
    n_col_blocks: int
    rationale: str

PROMPT = """You are a data analyst. Given a short description of the
matrix below, propose the number of row blocks and column blocks that
best explain its structure. Reply with JSON only.

{description}
"""

def propose(description: str) -> Proposal:
    raw = llm(PROMPT.format(description=description))
    data = json.loads(raw)
    return Proposal(**data)

The solver then runs from that starting point. A single iteration looks like this: 

prop = propose(describe(X))
assign = fit(X, n_row_blocks=prop.n_row_blocks,
                 n_col_blocks=prop.n_col_blocks)

score = evaluate(X, assign)
if score < best_score:
    best_score, best_assign = score, assign
else:
    prop = revise(prop, feedback=score)
Gotcha. The model will happily return a plausible-looking n_row_blocks for a matrix that has no real block structure. Always compare against a null model before trusting the proposal.

09:15 Segment 6 · 1 min 15 s · Wrap-up

6. Conclusion

Using an LLM as a structural agent rather than an end-to-end predictor is a narrow but useful role: it reduces the number of restarts the solver needs on sparse data. It is not a replacement for the probabilistic model, and it fails quietly when the data has no block structure at all.

The full implementation is on GitHub, and the notebook is archived on Zenodo.
